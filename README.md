# hexgod 0.17

Windows 海克斯大乱斗局内助手。默认入口 `hexgod.exe` 已更新为 0.17；同目录保留当前构建副本 `hexgod-0.17.exe`。旧版本及测试版 EXE 已清理。这是独立项目：runtime、tools、data、models 和 client-data 都位于本目录；移动或分享时保留完整目录，不要只复制 EXE。不依赖任何旧安装目录。

## 使用

启动后自动发现游戏、识别英雄和库存；选项出现时按左、中、右识别，正常点击卡片后自动确认所选。主界面取消手工补录和手工修正入口。自动记录数量、已选内容和同步状态保留在浮窗标题的提示及本局日志中。

浮窗保持置顶，在游戏前台时鼠标穿透，随游戏窗口跨屏。捕获游戏客户区后，从画面边框自动定位三张海克斯卡，再计算标题、点击及刷新区域；无需用户填写分辨率或 DPI。支持窗口移动、黑边、UI 缩放和宽屏布局。Ctrl+Alt+O 控制浮窗；Ctrl+Alt+H 可即时识别。截图导入仅供离线检查，不会记录为真实对局选择。

## 数据与推荐

生产数据直接使用 aramgg_client 的公开分发接口 `https://data.dtodo.cn/api/client/v1/config?locale=zh-CN`，当前 16.19.1，173 位英雄、211 个海克斯、305 个装备条目。完整目录在 client-data，每个下载文件校验清单的 SHA-256 后再激活版本，不上传日志或战绩。

海克斯优先级采用参考工程 augment-ranking.ts 的排名、梯队、选取率规则，保留屏幕卡槽顺序。胜率使用来源自身的样本版本；当前多数胜率来自 16.18，不冒充 16.19 样本。浮窗只显示名称、胜率和场数，来源版本与解释放入提示及日志。未公布的样本量显示为缺失。ARAMGG 是第三方国服统计整理，不是 Riot 官方胜率；某英雄某海克斯仅几千场时，胜率的随机误差和选取偏差都可能改变相近选项的次序。

装备浮窗常规栏最多 3 项，联动栏按实际候选数量显示 1–3 项，无候选时完全隐藏：常规装备综合胜率与样本量排序，延续 400 场先验及不足 250 场降权，并比较收缩胜率的保守下界；至少有三个不同购买方向的 250 场以上候选时排除不足 250 场的装备；先验使用同一出装队列的英雄平均胜率。界面显示原始胜率及完整场数，不显示排序分数。海克斯联动依据已选机制排序，升级只建议指定装备或明确可选装备，不把升级装备自身的属性或被动扩散成其他装备联动；多项强化各自的有效候选合并，任务指定装备优先；联动栏只显示装备名字，不显示胜率、场数、缺失占位或机制解释。无联动候选时浮窗宽 232，有联动时宽 320，高度约 200。指定装备购买完成后若没有其他联动候选，自动收起联动栏。玩家可自行选择，不会因未买某双鞋而只显示鞋子。两栏都过滤已购、部分唯一被动冲突及库存限制。

机制分析遍历当前 211 个强化描述，覆盖 9 个攻击特效词条以及升级、任务、暴击、属性转换、法力、最大生命值、治疗护盾、灼烧和装备急速。候选来自完整可购买目录。虚幻武器按英雄路线比较法强、物理和前排特效；保留装备本身充能、咒刃等触发条件，普攻专属效果不当作技能命中。已买联动核心不循环追买所有同类装备。英雄资源类型来自同版本 Riot Data Dragon，以免无蓝英雄被建议买法力装备。

该源装备统计标注队列 450，并非已选海克斯条件下的装备统计。修改后的机制路线不继承原核心组合胜率。精确匹配已有两项＋候选的历史三项组合时，在日志/后台结果中保留来源版本、场数和组合胜率；不把稀疏三项表累加为完整条件分布。随机强化变换与技能占位描述保留为需英雄/数据确认的情况。计划及分类见 MECHANICS-REFACTOR-PLAN.md、mechanics-audit.md。

更新同一来源数据：`.\runtime\python.exe -X utf8 aramgg_data.py`，成功后重启助手加载。断网时仍使用已完成校验的本地版本。历史 16.15 推荐代码只用于旧行为回归，不作为生产数据源。

## 日志

主界面“打开本局日志”，或查看 `logs/matches/<启动时间>-<对局序号>/`：

- `本局识别摘要.txt` / `summary.json`：选项画面数量、完整/部分识别帧、点击数量、已确认选择和未确认次数。
- `events.jsonl`：逐帧标题原文、置信度、匹配结果、自动定位的卡片坐标、各卡刷新、点击关联、确认/拒绝原因、屏幕/DPI/物理窗口坐标、OCR 耗时。
- `input.jsonl`：卡片点击与单卡刷新按钮的物理坐标。
- `input-health.jsonl`：每 5 秒记录 Raw Input 收包、左键、游戏前台、客户区计数，以及目标 HWND、卡片几何和确认状态。计数为本次进程累计值，可按时间差定位掉点。
- `title-*.jpg`：发生变化或识别不全时的标题裁图，每局至多 90 张。临时完整截图处理后删除。

events 每局达到约 8 MiB 时轮转一次；input 限约 1 MiB；input-health 限约 2 MiB 后轮转。连接与浮窗状态见 connection-status.json，其中 `clickCaptureMethod=raw_input+button_state`、`mouseInputClicks`、`gameForegroundClicks`、`gameClientClicks` 分别表示采集方式、左键次数、前台匹配次数和客户区次数。`clickListenerInstalled` 仅表示输入设备注册成功，实际收包须看 `rawInputPackets` 和 `lastRawInputAtMs`。异常见 backend.log / runtime.log。buttonStateChecks / buttonStateClicks 表示状态采样次数及接管点击数，rawInputStalled 表示游戏前台时原始收包停滞。逐次 inputSource 表示实际输入来源。日志只存本机，Git 不收录；迁移保留的历史日志不改写原始路径和旧版本号。历史对局目录可按需归档。

## 实现与验证

- WPF 使用 PerMonitorV2；Python 截图、卡片区域、鼠标事件统一采用游戏客户区物理坐标。
- OCR 使用参考项目同款 PP-OCRv5 检测模型、识别模型、字符字典；三卡标题带由实际边框位置生成。工具提示遮住两卡时只保留可见卡，不编造其余标题。
- 鼠标监听使用 Raw Input 和独立线程的只读按键状态采样；Raw Input 超过 250ms 无收包时，状态采样接管按下沿，两路去重，不使用鼠标钩子。刷新立即作废对应旧标题；不会把旧标题当作刷新后选择。点击之后仍需同一游戏窗口两帧确认面板消失。
- 不注入游戏、不读取游戏内存、不代替用户发送游戏输入。LCU/Live Client API 为本机只读 GET。

运行 `./verify.ps1` 执行 Python 回归、旧版固定数据回归、新数据 WPF 渲染回归和编译。

真实画面回归覆盖 1280×720、1920×1080、2560×1440、2560×1600、3440×1440，以及独立的 UI 缩放、偏移和遮挡。0.13 额外验证了本机 Raw Input 注册、原始数据包解析，以及从 10 月 11 日实战日志回放点击→确认→写入 summary 的生产链路；回放不等于实战输入送达验证。详见 [此次诊断报告](SELECTION-DIAGNOSIS-20261011.md)。

## 独立开发与本地 Git

直接双击 `hexgod.exe`。Windows x64 / .NET Framework 4.x，随目录 Python 3.12 和 OCR 依赖。环境覆盖项为 `HEXGOD_SOURCE_DIR`、测试开关为 `HEXGOD_TEST_LEGACY`，通常无需设置。

- `./build.ps1`：编译主程序。
- `./verify.ps1`：Python 回归、真实 WPF 场景和版本编译。
- `./runtime/python.exe -X utf8 -B audit_mechanics.py`：全英雄/强化/库存机制遍历。
- `tests/fixtures/`：随项目携带的回归截图及真实日志几何，不依赖外部参考仓库。
- `asset-manifest.json`：本地 Python 运行时及 ONNX 模型的逐文件 SHA-256。

本地 Git 收录源码、工具、数据快照、测试、文档及模型配置。runtime、ONNX 二进制、编译产物、缓存、个人设置和原始对局日志不进入提交，仍保留在本地完整运行目录中；仅有 Git 源码副本时需按资产清单恢复运行依赖。没有配置远端，也不上传日志。历史报告描述的是各自版本，当前行为以本 README 和生产代码为准。
