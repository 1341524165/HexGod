# 0.11：混合 DPI、漏识别、点击漏记与数据源迁移

## 从本机得到的证据

- 2026-09-28 晚间旧日志中，英雄与装备已经同步，但 `owned` 整局为空，多轮右侧选项为“待识别”。因此不能把问题解释成游戏接口全部没连上。
- 外接 ViewSonic VX27G58-2K：DISPLAY5，主屏，物理 2560×1440，DPI 96（100%）。内屏 BOE：DISPLAY1，物理 2560×1600，DPI 144（150%），桌面物理区域 `[2560,4,5120,1604]`。游戏配置为 2560×1440、WindowMode=2。
- 旧 WPF 清单只声明系统 DPI 感知，与逐屏截图及物理鼠标坐标不一致。旧 OCR 只有单行识别器，先依赖亮行裁切；这不是参考项目完整的检测＋识别流程。过去没有保留标题裁图，无法从旧日志逐张还原漏识别原因。
- 鼠标由 WPF 界面线程每 20 ms 查询一次按下状态，短点击或界面阻塞可能漏掉；旧点击可关联时间仅 1500 ms。选项消失判定也缺乏具体日志。

## 已实现

1. `app.manifest` / `App.config` 改用 PerMonitorV2。截图与点击统一采用实际游戏客户区物理坐标，浮窗跟随游戏所在屏幕。
2. `paddle_titles.py` 使用参考工程自带 PP-OCRv5 det/rec 和字典；`title_reader.py` 使用参考工程三卡标题带比例，保持卡槽，不靠说明文字填空。低置信度扩大文字边界重试。空白亮屏不会冒充选项面板。
3. `GameClickListener.cs` 使用独立线程接收鼠标事件，记录物理坐标；不拦截或注入点击。刷新按钮不算选中，并立即作废该卡旧标题。确认仍要求同窗口后续画面两次消失，失焦不算确认。
4. 新增逐局 events/input/summary 及标题裁图，能区分读到什么、是否匹配、哪张刷新、收到何种点击、是否确认以及超时原因。界面加入“打开本局日志”，取消手工补录与修正操作入口，浮窗显示自动记录状态。
5. `aramgg_data.py` 从参考客户端的公开数据接口下载和校验，`aramgg_engine.py` 成为生产推荐引擎。当前 16.19.1：176 个业务 JSON（173 英雄详情＋3 总目录），173 英雄、211 海克斯、305 装备条目。此接口不需要 API Key；此前把它当作必须有 Key 的判断不准确。
6. 海克斯优先级复用参考工程排名规则；装备从来源组合、实际库存和配方决定。来源中部分 situationalItems 的 winRate 字段是负值分数，改用明确的 wins/games，避免显示负胜率。缺失样本不转成 0，旧补丁胜率独立标注；低于 30 场的出门组合不进入出门提示。当前说明直接指定的任务装备保留额外提示。

## 参考工程能复用到什么程度

`reference/aramgg_client` 有完整的客户端窗口、截图、PaddleOCR、三卡匹配、数据分发加载与推荐显示实现，并非只有界面。此次采用其模型、字典、卡片区域比例、公开数据协议与排名规则；保留现有 WPF 外壳和本机只读接口。

在已审阅版本 0.2.17 的客户端源码中，没有找到“捕获玩家选卡并在面板消失后自动记入已选列表”的完整实现。点击确认与逐局诊断由本项目补足。公开接口只分发统计数据，没有提供服务端全部采集实现；不把客户端源码误称为完整数据后端。

数据也有边界：部分胜率样本仍是 16.18，英雄总样本量缺失，装备组合队列标识 450，参考实拍里的“裁决使”仍不在当前 211 项目录内。清楚识别出的未收录标题可显示并记录，统计留空。换来源不代表所有字段都有更大样本，也不代表获得了海克斯组合条件胜率。
