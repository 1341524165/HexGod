# 已选海克斯与装备路线重构计划

1. 建立独立机制分析器：使用当前已校验数据的完整描述、装备类别和被动，区分技能施加攻击特效、普攻特效、暴击、任务/升级、属性转换、法力、治疗护盾、灼烧、装备急速和英雄技能条件。遍历全部海克斯并输出可审查的分类与理由。
2. 将分析结果接入主要装备规划：任务/升级指定装备进入优先路线；机制装备从整个可购买目录挑选，不受常规出装表是否收录限制。保留库存、已投小件、鞋子和唯一被动约束；已购联动核心不重复推荐。
3. 处理组合与边界：攻击特效与技能触发联合分析；属性转化不等于伤害类型改变；随机变换/缺失技能描述不猜结果；相反转化或不相容机制显式提示。任务需要多装备时按任务要求处理替代组，避免现有去重规则阻断任务。
4. 分离机制与统计证据：机制排序不伪造条件胜率，改变后的路线不能继承原装备组合胜率。可匹配的三海克斯统计仅展示原版本组合参考，不合并重复样本、不冒充完整条件查询。
5. 验证：升级无尽、虚幻武器及全部攻击特效词条的正反例；多英雄、不同库存、已购、冲突、六格背包、多个已选顺序一致性；全英雄×全海克斯批量审计和 WPF 真正显示的下一件、机制理由及证据标签。
6. 构建新版本并更新默认入口，保留诊断日志；实战选择确认仍以真实日志为准。

验收重点：选择“升级：无尽之刃”后，无尽进入主要路线；法系选择“虚幻武器”后出现可触发的 AP 特效装备；仅提及攻击特效不会给所有英雄强推同一套装备；未公开联合样本不得显示推算条件胜率。

用户追加的 UI 要求：浮窗以“常规装备”和“海克斯联动”并列显示，每栏最多三项。常规栏按有效单件胜场/场数降序，样本够用时排除不足 30 场的极小样本；未购鞋子不阻断其它候选。联动栏按机制适配排序，任务/升级指定优先，无公开联合样本时不显示条件胜率；用户自行选择购买。内部路线继续用于机制解释及库存规划，不能锁死可见建议。
