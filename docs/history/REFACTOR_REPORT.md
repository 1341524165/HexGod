# hexgod 0.10 重构报告

对照日期：2026-09-27。参考仓库：[`valkia/aramgg_client`](https://github.com/valkia/aramgg_client)，本地检出提交 `e07cef86e7f88a16aa6046eabfc4cc7c4ab8da5a`，位置 `../reference/aramgg_client`。

## 结论与实现选择

保留 WPF、随包 ONNX 模型和本地统计，独立重构对局状态、OCR、点击确认和购买步骤。当前问题并不是必须切换 Electron 才能解决。所检出的参考提交没有 LICENSE/COPYING 文件，package.json 也没有声明许可证，因此没有复制其源码或将其截图打包进本程序；这里只对照架构并在本地使用原仓库测试图片验证兼容性。

参考实现也有自己的边界：其出装数据映射包含 coreItems/fullItems/itemExtensions，不能仅凭数组顺序断言拥有“相同前置装备、相同海克斯条件下”的购买路径胜率。第三方数据接口需要申请 API Key，本次没有使用其生产凭据，也没有接入远端上传。

## 发现的问题与处理

| 问题 | 0.9 的具体原因 | 0.10 处理 |
|---|---|---|
| 点击误记 | C# 点击后直接 AddOwned，Python 的消失确认从未接入真实点击链路 | 点击携带当时几何快照进入后端；两张不同、晚于点击的游戏帧确认消失，间隔至少 400ms，再记入 |
| 快速选择漏记 | 截图已捕获但 OCR 还没返回时，前端没有 geometry，直接丢弃点击 | 在游戏窗口中暂存点击；结果返回后仅关联点击前捕获、最多早 1.5 秒的帧 |
| 刷新按钮误触 | 旧卡片 hitbox 延伸到标题下方约 420px，覆盖卡片下面的刷新区域 | 缩小为卡片内部区域；刷新按钮不计入选择；识别到换牌取消待确认点击 |
| 单卡被遮挡时整帧拒绝 | 旧 OCR 推断要求至少两个已知标题 | 检查卡框结构，只读独立标题带；一个已知卡位也可识别，其余保留空槽 |
| OCR 读到描述 | 多布局、多个变体可能采到卡片说明和提示框 | 新增标题区域快速路径；宽区域描述不补位；特殊布局保留原预设回退 |
| 分辨率下降导致错字 | 720p 的“不祥契约”被读成“不样契约”后匹配失败 | 仅高置信度标题区域允许全标题唯一的一字符纠正，短词、歧义和描述不纠正 |
| 新海克斯消失 | 本地仅 206 项，“裁决使”不在数据包中 | 在另两项已知且卡框可靠时显示“未收录：标题”，可记录，胜率为空，不冒充已有统计 |
| 旧卡位复活或抖动 | 异步返回、旧截图、换牌与面板可见性混在 UI 控制器中 | 独立 AugmentViewState、请求上下文编号；相同卡位像素才可短时保留，换牌指纹变化清除旧名称 |
| 对局结束不清已选 | 仅用 Live API 掉线次数清库存，没有明确 gameflow | 可选只读 LCU 阶段 + 游戏进程/Live API 回退；跨局统一清理海克斯、库存、点击与截图上下文 |
| 短暂断连清错状态 | 无法区分接口失败与结束 | API 短暂失败保留对局；没有 LCU 时，游戏窗口消失且持续无接口 10 秒才结束 |
| 可能读到另一位玩家装备 | 将完整 Riot ID 和短名称混为一个名称集合 | 优先完整 ID，短名称必须唯一，不使用不匹配完整 ID 的弱名称兜底 |
| 浮窗阻挡点击 | Topmost/ShowActivated 不等于鼠标穿透 | 游戏前台时穿透、不激活；切回主窗口可拖动；其他前台应用自动隐藏 |
| 浮窗胜率错误 | 有条件推荐时浮窗仍固定读取 marginal winRate | 有条件样本时读取 conditional.winRate，标注统计依据 |
| 稀有收尾装抢首件 | 直接按持有装备的总体胜率/score 排序 | 将统计排序与购买策略分离；明确路线优先，其他英雄使用可解释的核心表启发式顺序 |
| 通用阈值抹掉英雄方案 | 首件使用率 40% 筛选把芮尔候选压缩到心之钢 | 有核心表的英雄不再被通用阈值覆盖；例如芮尔按基克、小法按卢登起步 |
| 后续装备冒充当前备选 | 无购买步骤与完整方案的区分 | 当前步骤与后续方案预览分开；库存失败时只显示“装备方案 · 待同步” |
| 买了小件仍跳另一套 | 未考虑配方与已经投入的金币 | 多重集计算组件抵扣；投入至少 1100 金且覆盖合成价 35% 的合理候选优先合成；阈值是启发式 |
| 重复装备/替代方案 | 只排除相同 ID | 追溯合成祖先、处理升级形态、鞋子及四类替代方案；满六格时不推荐无合成空间的第七件 |
| 狂徒门槛高估 | 当前小件生命值与合成后狂徒生命值重复相加 | 先扣除合成消耗的小件，再估算装备生命值门槛 |
| 难以查明实战状态 | 日志只在浮窗模式变化时写入；没开浮窗就不记录 | 推荐、库存、已选或阶段变化也记录；没有打开浮窗也可留诊断，不记录账号、聊天、令牌和截图 |

## 新的职责边界

```text
Controller.Session.cs → GameSessionState → 请求上下文失效 / 跨局清理
Controller.Capture.cs → BackendClient → backend.py（JSON 行协议）
                                      ├─ ocr_service.py → title_reader / title_match / 模型
                                      ├─ live_game.py + lcu.py → local_http.py（仅本机 GET）
                                      └─ recommendations.py → purchase_policy / item_order / synergy
Controller.Overlay.cs ← 当前选项 / 当前购买步骤 / 方案预览
```

OCR 和接口轮询仍使用两个独立子进程，防止接口超时阻塞截图。自动截图只在适用对局阶段执行：选项可见或点击待确认时约 500ms，普通对局约 1500ms；一次结束后才安排下一次，不堆积并发。真正 OCR 调用耗时也计入帧间隔，不能理解为固定 2 FPS。

## 验证结果

- `verify.ps1`：Python 回归、真实 WPF 渲染与状态测试、C# 编译。
- 全 173 位英雄逐步购买至六格的回放，检查重复购买、可购买性、替代装备与价格。108 位英雄的首项相对 0.9 发生变化；这是算法变化量，不是胜率提升证明。
- 原仓库真实截图：三卡为 `未收录：裁决使 / 超凡邪恶 / 神射法师`；遮挡画面仅识别左侧 `不祥契约`；描述干扰画面不匹配任何强化。720p 缩图亦验证。
- C# 场景覆盖 gameflow、同英雄跨局、掉线/重连、时钟回退、快速点击缓冲、旧帧、换牌、出门装优先级、条件胜率与核心路线。
- 逐英雄结果和原版对照见 [refactor-audit.md](refactor-audit.md)，机器结果见 [refactor-audit.json](refactor-audit.json)。图片仍在参考仓库，未复制进发布资源。
- 浮窗离线渲染：`.cache/starter-rell.png`、`starter-vayne.png`、`items-hecarim.png`、`items-veigar.png`。

## 尚不能由这些测试证明的事情

本机验证时没有运行中的游戏，国服 WeGame 的 LCU 发现、不同 HUD 缩放、超宽屏、独占全屏和实际窗口点击穿透仍需要实局验证。现有真实截图来自同一参考仓库，不能推导通用 OCR 成功率。

统计仍为本地 **16.15 / 2026-08-02**。核心方案原始生成时间为 2026-06-02，缺少逐件购买样本；全英雄顺序属于启发式，只有人马两件是明确配置的人工路线。它们都不是当前版本的最优路径证明。海克斯机制建议继续单列，既有数据不足以证明“海克斯 + 已出装备前缀”的完整条件胜率；本次没有伪造或替换统计。未收录强化只能记录名称，暂时没有效果规则和胜率。重启程序仍不恢复本局已选，快捷选择发生在任何可用截图之前也无法可靠倒推。

0.9 修改前源码保存在 `.cache/pre-refactor-0.9`。旧 EXE 与新版本共用当前目录 Python/XAML，单独运行旧 EXE 不等于恢复旧源码；回滚时需恢复备份并按旧 build.ps1 重新编译。
